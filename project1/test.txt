# Slide 2 – Project Goal & Business Problem

Every day, banks and financial institutions receive thousands of loan applications.

Traditionally, these applications are reviewed manually by loan officers.

While experienced underwriters make good decisions, the process has several challenges.

First, manual review is time-consuming.

Second, different officers may recommend different loan amounts for very similar applicants, leading to inconsistent decisions.

Third, manual processing increases operational costs and slows down approvals, which negatively affects customer experience.

The goal of this project is not to replace human decision-making but to support it.

The machine learning model analyzes a borrower's financial profile and recommends an appropriate loan amount based on historical patterns in the data.

This creates a faster, more consistent, and data-driven recommendation process while allowing loan officers to make the final lending decision.

---

# Slide 3 – Dataset Overview

Now let's look at the dataset used to train the model.

The dataset contains approximately 15,000 borrower records with 17 columns.

Since the output is a continuous loan amount, this is a supervised regression problem.

The target variable is **recommended_loan_amount**.

The input features describe the borrower's financial and personal profile.

Examples include:

* Age
* Annual income
* Credit score
* Debt-to-income ratio
* Savings balance
* Employment history
* Property ownership
* Previous loan defaults
* Loan term

These features collectively provide enough information for the model to estimate a suitable loan amount.

The dataset contains a mix of numerical and categorical variables, which required preprocessing before model training.

---

# Slide 4 – Data Preparation

Before building any machine learning model, the quality of the data must be improved.

The notebook begins with data exploration to identify missing values, outliers, and inconsistencies.

One interesting issue appeared in the savings balance column.

Some borrowers had unrealistic savings values.

Instead of simply removing those records or replacing them with the average, I designed an income-based replacement strategy.

I grouped borrowers based on years of employment and estimated more realistic savings values using their income.

This approach preserved relationships between financial variables while reducing unrealistic values.

Cleaning the data before training improves both model accuracy and reliability.

# Slide 5 – Exploratory Data Analysis

Exploratory Data Analysis helps us understand the relationships within the data before building predictive models.

The notebook uses SQL-style analysis together with visualizations.

I analyzed variables such as:

* Age
* Annual income
* Savings
* Debt ratio
* Employment years
* Credit score

The first correlation heatmap shows the relationships before cleaning.

After cleaning, we can see stronger and more meaningful correlations, indicating that noise was reduced.

The savings versus income scatter plot also became much more realistic after preprocessing.

The distribution of savings across years of employment shows that savings generally increase with work experience, which aligns with real-world financial behavior.

---

# Slide 6 – MICE Imputation vs My Approach

For missing savings values, I compared two different strategies.

The first was MICE, which is a widely used multiple imputation technique.

MICE estimates missing values using many variables simultaneously.

While it is very flexible, it sometimes produced savings values greater than annual income.

Although this may happen in rare situations, such values were unrealistic for many borrowers in this dataset.

My custom approach introduced business constraints by estimating savings based on income and employment characteristics.

This produced more realistic values while preserving logical financial relationships.

This comparison demonstrates that domain knowledge is just as important as sophisticated algorithms.

Sometimes a simpler method aligned with business rules performs better than a statistically complex method.

---

# Slide 7 – Modeling Approach

After preparing the data, I trained several regression models.

The models evaluated were:

* Linear Regression
* Random Forest Regressor
* XGBoost Regressor

Linear Regression served as a baseline model.

Random Forest improved performance by capturing nonlinear relationships.

However, Random Forest produced the best predictive accuracy.

Random Forest builds multiple decision trees using different random subsets of the training data and features. The final prediction is obtained by averaging the predictions from all the trees, which improves accuracy and reduces overfitting.

It handles nonlinear relationships, interactions between variables, and complex financial patterns very effectively.

After training, I saved the final model as a pickle file.

The deployed Streamlit application loads this saved model directly for predictions without retraining.

---

# Slide 8 – Performance

I evaluated three regression algorithms: Linear Regression, Random Forest, and XGBoost. Linear Regression served as a baseline but couldn't capture the nonlinear relationships in the data. Both ensemble models performed significantly better. After comparing the evaluation metrics, Random Forest achieved the highest R² score and the lowest RMSE on the test dataset, so I selected it as the final model for deployment.

An R² value close to 1 indicates that the model explains nearly all variation in the target variable.

This suggests that the model learned the relationships in the training data very effectively.

I also investigated whether features showing zero correlation with the target should be removed. After retraining and evaluating the model, I compared the results to determine whether feature reduction improved performance or simplified the model.

In addition to evaluating the model on a single test set, I also performed 5-fold cross-validation. The model achieved a mean R² score of approximately 0.9981 with a standard deviation of only 0.00037. This indicates that the model's performance is highly consistent across different subsets of the dataset and is not dependent on a single train-test split.

The feature importance plot shows that annual income, credit score, debt ratio, and savings contribute the most to the recommended loan amount, while some demographic variables have relatively smaller influence.

These steps help ensure the model generalizes well beyond the training dataset.
